# 拾页排列器 · 本地试用版

## 安装（一次）

1. 使用 Figma 桌面客户端，主菜单 → Plugins / 插件 → Development / 开发 → Import plugin from manifest / 导入插件清单。
2. 选择本目录的 `manifest.json`。这是开发插件，不需要发布到社区。
3. 在 Figma **桌面客户端**打开目标设计文件，运行开发插件「拾页排列器 · PagePick」。本地开发插件的官方测试环境是客户端，不承诺能直接在网页版运行。
4. 插件内设置间隔（默认 500），点击“开启客户端接收并隐藏”。插件持续接收新增画板；隐藏面板不会退出插件。
5. 在浏览器扩展设置选择“Figma 客户端”＋“本地助手自动粘贴”，填写准确的客户端窗口标题并保存。
6. 回到 Aside 来源网页点击拾页图标。助手将内容粘贴到客户端，插件移动新增画板。
7. 客户端模式的间隔在插件内配置；浏览器设置的间隔用于网页桥接模式。停止自动接收请在 Figma 中关闭正在运行的插件。

### 网页桥接模式（实验性）

extension/plugin-bridge.js 提供网页 iframe 通路，但需要该插件能在网页编辑器运行（例如完成合法发布后）。本地 manifest 导入并不能被视为网页端可运行。不要为了测试未就绪的网页通路反复捕获。若已有可运行的网页版本，可选择网页端＋排列器，并先通过“检测插件”。

## 使用

仍然点击来源网页的拾页悬浮图标。本地助手保留原有系统粘贴工作；插件通过真实 Figma 节点修改位置，不再通过属性面板输入坐标。

- 第一张确认导入后移动到 (0, 0)。后续右移，间隔取扩展设置，默认 500。
- 排列器用本次导入前后的顶层画板 ID 差异识别新画板，并等待尺寸和子图层数量稳定。
- 成功坐标保存于当前 Figma 页面的插件数据；失败不清空，不推进。
- 粘贴迟到或确认超时，点击插件“重试确认”。只处理原任务，不再次粘贴。
- 出现多个新增对象或切换页面时停止排列，避免改错。取消待命后可继续下一次捕获。
- “重置记录”只清除当前页的排列锚点，不移动已有内容；下一张重新从原点开始，可能与原点已有内容重叠。
- 插件运行期间不要同时手动新建其他画板，以免新增对象存在歧义。

## 通信与限制

浏览器通过目标 Figma 标签页向运行中插件的 iframe 发送限定命令。插件 UI 再通过 Figma 官方 UI 消息接口交给插件主线程。无需额外本地服务器、开放端口或网络域名。此 iframe 通路必须在实际 Aside/Figma 环境中验证；连接检测失败会阻止自动粘贴，不静默退回旧排序方式。

本试用版优先测试“浏览器捕获＋本地助手＋客户端开发插件自动接收”。客户端模式直接观察新增画板，无需 iframe 桥接。选择“仅复制”后手动粘贴，已开启自动接收的客户端插件同样会处理新画板。

插件不能作为永不关闭的后台服务；关闭、切换到其他插件后需重新启动。

## 验证情况

已通过模拟 Figma API 测试：首张原点、后续间隔、超时保留记录、迟到导入重试、重复提交幂等、多对象拒绝、保存失败回滚、跨页中止。真实 Aside 连接、插件运行中系统粘贴及连续导入仍待实际验收。
