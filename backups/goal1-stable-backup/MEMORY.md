# 拾页 · PagePick 项目记忆

更新日期：2026-11-03。

## 用户最重要的要求

本项目的网页捕获能力已经由用户提供的竞品实现。用户已验证竞品捕获结果可以手动粘贴到 Figma。优先复用已有实现，不要重新开发网页转图层引擎，也不要扩展到无关功能。

用户指定的三个目标，优先级依次是：

1. 点击网页常驻图标，自动捕获并自动粘贴到 Figma。
2. 自动展示并捕获 hover、菜单、选中和弹框等交互状态。
3. 后续通过 AI 批量采集、粘贴，并按网页菜单分类命名整理。

当前必须先收尾自动粘贴和排列，暂不添加新功能。

## 用户对这次开发的反馈与必须吸取的教训

用户明确指出：捕获代码是现成的，自动粘贴和排序反复开发一天仍未稳定，非常费劲。助手承认连续叠加未经实际验证的方案、反复改变路线、让用户重复试错，甚至破坏原本能用的流程，是执行问题。

后续必须：

- 保留已可用的捕获代码，只修复有实际证据支持的失败点。
- 不再无休止叠加快捷键、模拟粘贴和属性面板补丁；失败先读取实际错误。
- 自动粘贴由现有本地助手配合扩展完成，排列优先由 Figma 插件通过真实节点 API 设置坐标。
- 不让用户承担每次代码修改后的重复测试；尽可能由助手实际验证后交付。
- 编译、语法检查、模拟 API 测试通过不等于实际功能完成。
- 不要声称“保底百分百成功”；必须有实际导入和坐标回读证据。
- 回答简洁、说明真实状态，不反复承诺已经修好。

## 绝对不能改动的窗口行为

用户明确要求：不要改变 Figma 客户端窗口的大小、位置或最大化状态。

旧助手在激活窗口时调用 `ShowWindow(target, 9)`，导致最大化窗口被还原。已经删除这一调用并重新编译。当前只切前台；目标最小化时提示用户先打开，不自行改变窗口状态。后续不得重新引入自动还原或调整窗口尺寸。

## 排列规则

- 新序列第一张导入后设置 X=0、Y=0。
- 后续 X=上一张成功画板的 X+宽度+配置间隔，Y=0。
- 默认间隔为 500 px，可配置。
- 不以用户随意选中的旧画板作为新序列基准。
- 只有真实新增画板已经识别，且坐标修改、回读确认成功后，才更新持久位置记录。
- 中间捕获、粘贴或排列失败，都保留最后一次成功位置，不清空、不推进。
- 下一次从最后一次成功位置续排。
- 只重试移动同一个节点，不因排列失败而重复粘贴。
- 不能唯一确认本次对象时停止修改，避免移动无关内容。
- 重置记录不移动或删除已有画板。

## 当前实现与真实状态

- 用户主要在 Aside 浏览器中操作。配置支持 Figma 网页端和客户端、本地助手自动粘贴和仅复制手动粘贴。
- **目标①核心排列已突破并获用户实测通过**：
  - 彻底弃用了原有脆弱的属性面板模拟输入（`SendInput` 打字输入坐标）与轮询 `COMMIT`。
  - 架构确定为：浏览器扩展捕获 → 本地助手激活窗口并发送 Ctrl+V → Figma 插件内部基于 `selectionchange` 选区监听（新粘贴物 100% 自动被选中）毫秒级捕获新粘贴画板，配合 `documentchange` 与轻量轮询三重兜底。
  - 直接调用原生节点 API（`node.x = targetX; node.y = 0`）精准瞬移。
  - 成功回读并确认坐标后，计算 `nextX = targetX + width + gap` 并持久化记录到当前页插件数据。
  - 用户实测确认：吸附顶部 Y=0，向右按 500px 间隔自动排列功能已正常工作！
- 插件客户端模式无需隐藏 UI，提供实时运行状态指示、当前画板位置日志与重置按钮。
- 本地助手在 `native-host`，使用 Windows SendInput；激活窗口只切前台，严格保证不改变 Figma 客户端窗口大小或最大化状态。
- 网页端实验性通路保留，但目前主推荐并已验收的链路为：Aside 捕获 → 本地助手 → Figma 客户端 → 拾页排列器插件。

## 捕获和按钮行为

- 正常捕获不强制刷新：先滚动加载、捕获；捕获上下文或连接异常时才刷新重试一次。
- 权限、配置、无限滚动上限等错误不应盲目反复刷新。
- 粘贴、排列失败不触发重新捕获。
- 捕获前逐段滚动，等待懒加载和图片，恢复原滚动位置；有无限滚动停止上限。
- 常驻按钮外框含边框为 48×48 CSS px。
- 只在真正捕获时暂时隐藏按钮，捕获完成立即恢复，并有错误恢复与超时兜底。
